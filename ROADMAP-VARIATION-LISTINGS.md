# ROADMAP — VARIATION LISTINGS

This roadmap is the authoritative task ledger for the dedicated Inventory API variation-listing workflow. It is separate from legacy Single/Lot; task IDs (`YP0`–`YP9`), `YPSBX-*`, `.local/you-pick-sandbox/**`, and worktree names are retained only as historical/repository provenance. Detailed product invariants are consolidated under **Permanent constraints** instead of repeated before the task tables.

## Execution routing

| Label | Use |
| --- | --- |
| `ChatGPT + DeepSeek fallback` | Direct ChatGPT preferred; DeepSeek only for bounded repo/code/test execution without DB/container/recovery complexity. |
| `ChatGPT + Codex fallback` | Direct ChatGPT may start; Codex handles architecture/recovery/concurrency or Docker/Supabase/PostgreSQL execution. |
| `—` | Codex default for unfinished work. |
| `Operator + Sol review` | Live eBay/database execution or buyer-facing verification; explicit authorization required. |

**Sizing:** private single-user app; prefer the smallest maintainable design. Add persistence/checkpoints/constraints only for demonstrated corruption/replay risks or immediate downstream requirements; JSONB is appropriate for immutable evidence that is not queried relationally.

## Permanent constraints

- **Isolation:** variation listing is a separate workspace/domain from legacy Single/Lot; existing Single/Lot intake, generation, pricing, publishing, reconciliation, deletion, routes, allocation, and SKU grammar remain unchanged.
- **Group/condition:** one shared eBay condition contract per group. Copies may retain different internal conditions only when compatible with that shared contract; mixed-condition publication is forbidden.
- **Inventory model:** groups are long-lived buckets. One variation = one immutable selector + SKU; duplicate physical copies share it and derive quantity. Local additions/replenishment/price/image changes publish only through explicit staged revisions.
- **Copies/images:** each copy owns immutable group/variation/copy front/back R2 identity; exactly one copy is representative and selling it does not auto-switch the representative. Published child images are seller-owned EPS `[front, back]`; omit group-level `imageUrls`.
- **Intake:** explicit sticky target group + sticky manual tier + duplicate-copy mode; never infer variation intake through Single/Lot capture state.
- **SKU/identity:** immutable group UUID → `VL-G-<GROUP_UUID_HEX>` remote key; immutable variation UUID/selector and `<category-prefix>-<bucket-token>-<six-digit-serial>` SKU. `(category,bucket)` namespaces are unique, allocation is monotonic/fail-closed, duplicates share SKU, and selector labels contain no stock/price/position/serial/UI suffixes. Offer/listing/Media identities remain separate historical facts.
- **Pricing/AI:** only `$0.99/$1.49/$1.99/$2.49`; no SoldComps/Browse/market/automatic repricing. Gemini is the only model provider and may generate identity/review/group content, never price.
- **Item specifics:** YP1.4 category `261328` contract is authoritative: persist variation metadata separately; group aspects contain only truthful common values; omit heterogeneous optional/recommended values; block/regroup required no-common values; only custom `Card` may vary as an eBay pivot.
- **Remote snapshots/order:** complete group snapshots only. Application selector order is authoritative; reconcile eBay `variantSKUs` by exact membership, not response order.
- **Media:** Media IDs are opaque and validated by trusted eBay URI boundary. Inventory cleanup does not imply Media deletion; current EPS resources may expire naturally.
- **Quantity/cleanup:** quantity zero hides one variation without disrupting others and does not require restoration before cleanup. Published groups withdraw before Inventory deletion; abandonment is pre-publication or requires exact proof withdrawal is unnecessary.
- **Orders/sales:** sold/order evidence protects identity/history from destructive erasure; unresolved matching fails closed. Do not add sold/order persistence until YP8.1 proves the real order-line contract.
- **Mutation/recovery:** Inventory API owns post-creation mutations. Read before write; unknown remote state never permits blind replay/destructive cleanup. Recovery remains a small crash-safe frozen-revision/checkpoint journal—no generic event sourcing/workflow engine/resource registry/timeline/multi-tenant or speculative concurrency framework.
- **Persistence:** use relational columns for corruption-preventing identity/ownership/order/status/FKs/uniqueness and JSONB for immutable evidence not requiring relational queries. Dedicated variation persistence remains namespaced; no manual quantity column/session state on groups.
- **Database/live gates:** completed coding never implies hosted DB/data or production eBay authorization. Shared migrations apply once through the canonical linked workflow after separate explicit approval; feature worktrees share the same hosted DB. No raw `.local/you-pick-sandbox/**` artifacts are committed; only sanitized durable conclusions are tracked.
