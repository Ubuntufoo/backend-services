## Current working constraints

- One eBay condition applies to the entire You Pick listing. The initial design must group only cards that satisfy the selected minimum condition tier.
- Each selectable card remains an independent child SKU, inventory item, offer, price, quantity, and front/back image pair beneath one buyer-facing listing.
- The implementation must not modify the behavior or contracts of existing Single and Lot intake, generation, pricing, publishing, reconciliation, or deletion flows.
- The frontend must expose You Pick through a separate tab/workspace so the user cannot confuse it with Single or Lot preparation.
- The observed listing has 87 selector values; this disproves a universal 30-value planning rule but does not create a new universal limit.
- Effective selector, image, and group-size limits require official metadata, category/account checks, sandbox proof, and an explicit operational cap.
- No eBay write is allowed from this worktree until local environment/resource isolation is proven and the pilot execution is separately authorized.
- Exact next task: separately review and implement the YP0.6 mutation path, then require explicit write authorization before any Sandbox execution. The successful read-only evidence is run `20260804T133811Z-2c5506`; the current YP0.5 CLI remains read-only and rejects every `--execute` invocation.
